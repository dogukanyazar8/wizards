# Prisma 7 UAT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the PostgreSQL data layer to Prisma 7 with an ESM generated client, `@prisma/adapter-pg`, explicit seeding, safe disposable verification, and no application data-layer regression.

**Architecture:** `packages/db/src/prisma.ts` becomes the sole generated-client and adapter boundary. It reads validated pool options, creates one `PrismaPg` adapter-backed client per long-lived process, and exposes a short-lived factory for seed/E2E/verification callers. `packages/db/src/index.ts` preserves application imports by re-exporting that boundary. Prisma CLI configuration moves to package root, while generated source remains a reproducible ignored artifact.

**Tech Stack:** Node 24.18+, pnpm 11, TypeScript 6 API plus TS7 CLI, Prisma 7, `@prisma/adapter-pg`, PostgreSQL, `tsx`, Next 16, Tauri 2.

```js
export function assertDisposableDatabaseUrl(value) {
  const url = new URL(value);
  const loopback = new Set(["127.0.0.1", "::1", "localhost"]);
  const database = url.pathname.slice(1);
  if (
    url.protocol !== "postgresql:" ||
    !loopback.has(url.hostname) ||
    !database.endsWith("_prisma7_verify")
  ) {
    throw new Error(
      "PRISMA7_VERIFY_DATABASE_URL must use loopback PostgreSQL and end in _prisma7_verify.",
    );
  }
  return url;
}
```

The runner must validate the URL before every spawned command, then run from
`packages/db`: `prisma migrate deploy`, `prisma db seed`, disposable CRUD smoke,
`prisma migrate reset --force --skip-seed`, the second deploy/seed/smoke cycle,
and `prisma migrate status`. It must pass the validated URL only through child
environment, never log it, and exit non-zero on any child failure.
